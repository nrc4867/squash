# Recipe reference

What a recipe can name, generated by `generateSchemas` from the code; a test fails when these files are stale. The recipe's own fields are described in `schema/recipe.schema.json`.

| file | answers |
| --- | --- |
| templates.md | each template's rest, outline length, what each view sets, sockets, joints with hinge and limits, areas, patches and parameters with meanings |
| plans.md | each plan's root, sockets, slots and palette |
| part-parameters.md | dotted part parameters (`move.*`, `socket.<n>.*`, `joint.<n>.*`, `generic.*`, `join.ink`, `rig.reach.*`) and the recipe fields that write them |
| frames.md | body space, which way u, v and each view's y run for a part resting each way, and which way `degrees`, `lean`, `turn` and `twist` move a bone |
| face-and-clothes.md | mouth group roles and controls; region borders, corners and two-tone faces; how a painted eye faces and lands on its head, wrapped or flat; how garment fit, covers, redraws and swaps combine |

For a built recipe, `tools/recipe.sh probe <recipe> ...` prints the same frame facts for its own parts: u and v at a body point or a face place, the body point at a u and v, and each part's extent, joints and sockets.
